# 授权与执行连接

此文说明当前设计，不记录任何开发者或用户的账号状态、模型套餐、真实调用、授权链接或登录凭据。

## 状态不能互相替代

已安装、原应用已登录、CLI 已认证、目录中有模型、连接验证成功和任务完成是不同状态。只有受支持且已就绪的执行器及模型才能加入自动流程。目录可见不证明每个模型均有当前权限或额度。

## 登录入口

- Codex、Claude Code 使用受支持的官方 CLI 浏览器授权，凭据继续由原产品保存。
- CodeBuddy 使用官方 ACP 授权；微信和国际账号入口分别显示，不从 IDE 的登录状态推定独立 CLI 可用。
- WorkBuddy 仅在受支持的同厂商官方运行入口中复用授权；授权不会作为应用公开状态返回，也不会转发到其他产品。
- 需要原客户端管理账号的入口只打开原应用。没有执行适配器时，重新登录不能使它变成自动执行器。
- 自定义 API 密钥由用户显式填写并经系统安全存储加密。空密钥编辑保留已保存值；界面不回填密钥。

登录必须由用户操作启动。等待期间可取消，不将原始认证 stdout/stderr、令牌、账号身份或验证码传入界面。完成授权后重新检测，必要时显式验证连接；“已打开浏览器”不是登录成功。

## 验证连接

验证可能产生少量真实推理用量。应用显示本次实际验证的模型和思考档位；一个模型的成功不能证明整个目录均可用。超时、取消、认证失败和模型生成尚未结束分别处理，不用收到响应字节推算 Token。

自动探针只能选择已声明能力的模型与较低档位。用户明确指定的模型和思考强度不静默替换。账号撤销、网络、套餐或厂商版本改变后，连接状态可能失效。
